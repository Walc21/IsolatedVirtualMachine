# Manifesto v1

`schemaVersion: 1` é obrigatório. Campos desconhecidos são rejeitados. Não coloque secrets neste arquivo. Nome usa `[a-z][a-z0-9-]{0,62}`; CPU 1–64; RAM 512–262144 MiB; disco 8–2048 GiB. Imagem v1 aceita somente Ubuntu cloud (`images:ubuntu/<release>/cloud`), com release de uma allowlist verificada pela instalação Incus antes da criação.

Campos: `name`, `os {distribution, release, desktop?}`, `resources {cpu, memoryMiB, diskGiB, pool}`, `network {mode, bridge?}`, `mounts [{host, guest, mode}]`, `security {profile}`, `software {apt[], pip[], npm[], cargo[], go[]}`, `environment {NOME: VALOR}`, `metadata {template?}`. A imagem é derivada da versão Ubuntu como `images:ubuntu/<release>/cloud`. Rede v1 aceita `offline` e `normal`; `normal` requer bridge explícita. O wizard não adiciona NIC no modo offline. Sem mounts é o default. Pacotes são validados como nomes simples ou versões exatas; ausência de software, desktop e variáveis não gera `cloud-init`.

`os.desktop` ausente significa headless. Valores aceitos: `gnome`, `kde`, `xfce`. A seleção instala respectivamente `ubuntu-desktop-minimal`, `kubuntu-desktop` ou `xubuntu-desktop` via `cloud-init` no primeiro boot. Esses metapacotes constam nos repositórios Ubuntu 22.04, 24.04 e 26.04; versões e dependências continuam sujeitas aos repositórios da data de instalação. Modo offline pode impedir o download. A imagem cloud não cria uma senha de login gráfico: depois de iniciar, use **Configurar login gráfico** para abrir um terminal Incus interativo que executa `passwd ubuntu` dentro da VM antes de entrar na console VGA. O manifesto não armazena essa senha. A ação exige a VM em execução e o agente Incus funcional no guest.

`security.profile` é opcional para compatibilidade com manifestos v1 antigos; na ausência dele, o valor é `custom`. O wizard novo inicia em `maximum-isolation`, que exige rede offline e nenhum mount e impede que a GUI conceda esses acessos depois. `normal-development` e `custom` permitem somente concessões explícitas do manifesto. `restricted-development` exige `network.mode: restricted`, bridge explícita e uma lista `network.egress` com regras `{kind: domain|ip|cidr, value, port, protocol: tcp}`. A configuração Incus registra o perfil selecionado; a tela de permissões sinaliza quando dispositivos efetivos violam `maximum-isolation`. Isso não impede modificações feitas diretamente por um administrador Incus.

O manifesto aceita até 16 mounts. Cada origem deve ser uma pasta específica dentro do HOME, sem symlink nem caminho sensível conhecido. Origens e destinos duplicados ou aninhados são recusados para manter o significado de RO/RW inequívoco. O wizard edita todos os mounts declarados em um manifesto importado.

`environment` é opcional e aceita até 32 pares de texto simples, sem espaços nem caracteres de shell, com nomes em maiúsculas. Nomes reservados e nomes que parecem credenciais são recusados. Essa validação é apenas uma barreira contra erros comuns, não identifica todos os segredos. Valores são exportados no YAML, aparecem na configuração Incus e são acrescentados a `/etc/environment` da VM (permissão `0644`). Portanto, use somente dados públicos ou não sensíveis. Os valores são lidos em novas sessões de login; processos já em execução não recebem atualização automática. O wizard tem 13 etapas e mostra o `cloud-init` gerado antes da revisão.

O `cloud-init` é renderizado como YAML estruturado para `cloud-init.user-data`, com `packages`, `package_update: true` e, quando necessário, `runcmd` em formato de lista de argumentos. Pacotes Python vão para `/opt/isolatevm/python`; pacotes npm são instalados globalmente **dentro da VM**. `cargo` exige `crate@X.Y.Z` e executa `cargo install --locked --root /usr/local --version`; `go` exige `módulo/comando@vX.Y.Z` e instala o binário em `/usr/local/bin` via `GOBIN`. Ambos instalam somente dentro do guest e dependem de rede no primeiro boot. A versão exata reduz variação, mas ainda depende da versão do compilador, das dependências publicadas e da disponibilidade dos repositórios. Nenhum comando shell livre é aceito. Preview diferencia operação planejada de estado efetivo.

As caixas do catálogo de software são apenas um editor para `software.apt`; nenhum campo implícito de preset é necessário para reproduzi-las. Ao importar um manifesto, os pacotes conhecidos são marcados na categoria correspondente e os demais aparecem no campo APT personalizado. A ordem original dos pacotes importados é preservada enquanto a seleção não muda. Docker (`docker.io`) e Podman (`podman`) são instalados somente no guest; nenhum socket ou dispositivo do host é anexado por isso.
